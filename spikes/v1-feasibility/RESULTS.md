# V1 feasibility slice: bounded results

**Status: bounded feasibility slice completed, not a V1 design freeze or production clearance.** Generated proving keys use public test entropy and must never secure real assets. Candidate Circom/snarkjs dependencies have GPL-3.0 licensing questions. SOL custody was exercised on Devnet; token custody was tested only with LiteSVM and a local USDC-like test mint, not canonical USDC.

## Added recovery integration, 14 October 2026

The new path uses 24-word research phrases to derive both spend and view keys. `recovery/history.test.mjs` verifies paginated standard-RPC replay against mocked finalized transactions and a pool-account snapshot, including an inner pool instruction in a v0 transaction with a loaded program address; missing transactions, malformed payloads, mismatched commitments, and replayed nullifiers reject. `candidate-circuits/scripts/prove-restored-journey.mjs --emit` built valid shield, one-input transfer, and current-holder public-exit proofs from the restored notes for SOL; `--asset1` repeated this for the local USDC-like token. All 13 pool LiteSVM tests pass, including both restored journeys. The SOL shield used 128,505 CU, transfer 183,207 CU in a 1,514-byte v1 transaction, and exit 119,505 CU after approval revocation and guardian pause. The token path used 131,417, 187,674, and 123,790 CU respectively, with a 1,679-byte transfer. These are test-only keys and tiny asset amounts.

The browser journey derives keys, encrypts outputs, replays synthetic public instructions, builds witnesses from restored notes, and proves locally. On the 8 GiB M1, 100 restored-state transfer/exit proofs each yielded warm p95: Brave 1,878/1,048 ms, Firefox 1,328/713 ms, and Safari 1,647/881 ms. A separate three-run Firefox smoke check verified the local-token restored-state transfer and exit path. Local loopback artifact loads were 21/102/67 ms respectively; they are **not** first internet downloads. The journey runs one shield proof and uses public fixture phrases. These measurements do not include actual RPC backfill, wallet signing, or validated peak process memory.

Safari's first continuous 100-run two-input transfer did not complete before its 800-second total timeout; progress reached proof 77. A rerun with a sufficient timeout completed 100 verified proofs in one session: first proof 2,876 ms, warm p95 2,443 ms, warm maximum 2,944 ms. This does not reproduce a continuous-session stall. Four earlier fresh-page batches were much slower (combined warm p95 11,958 ms, maximum 14,224 ms), so conditions caused material variability that has not been isolated. Fresh-page Safari withdrawal runs completed 100 one-input proofs (warm p95 7,536 ms) and 100 two-input proofs (warm p95 13,140 ms). Firefox's separate 100-run two-input transfer, one-input withdrawal, and two-input withdrawal warm p95s were 2,168, 1,401, and 2,220 ms. During the latter part of the Safari continuous run, 36 five-second RSS samples observed a WebContent high-water of 1,017,168 KiB (~993 MiB) and 1,111,360 KiB (~1,085 MiB) summed across WebKit processes. These are sampled RSS values, not true peak/private memory, and the sum may double-count shared pages or include unrelated WebKit processes. Saved browser results are under `candidate-circuits/generated/`.

**Remaining recovery gaps:** The isolated pool now rejects arbitrary 32-byte shield payloads and malformed packed records, and checks each embedded commitment against its proven output signal. This is a structural check; the circuit still does not prove that encrypted plaintext opens to that commitment. The pool retains 32 roots; 32 later leaf appends (for example, 16 two-output transfers) can evict a witness root before proof submission. Expiry and retry behavior need live measurement. Approval-root changes publish no leaf data from which a new device can reconstruct a general approval witness. The fresh-profile recovered exit now finalized for this single-origin Devnet fixture; general witnesses and archival retention remain unproved.

## What the slice established

The candidate pool checks the current approval root at execution, while public exit omits approval and pause checks. The Devnet trial confirmed that the current holder could publicly exit a transferred note after revocation and pause, provided a valid witness and fee payer. Local tests also cover pending notes. Public exit reveals origin and binds recipient; private payouts, fee amount, output commitments, and exact output payload bytes are proof-bound. The pool hashes the payload before accepting it. This prevents a relayer from changing ciphertext after proof generation, but the circuit does **not** prove encrypted plaintext matches a note. The fixture separately decrypts and checks each commitment before proving and after unpacking supplied records. The Devnet journey exercised browser proving, Jupiter signing, SOL custody, and independent fresh-profile recovery for one public test origin; this does not establish production security or general recovery.

## Gates still open

1. **Recovery and history durability:** Choose a durable, bounded ciphertext publication and independent backfill design, then restore on a fresh device with the reference indexer, ASP, and relayer offline. Measure full-history envelope scanning and transaction-history availability from chosen RPC providers; [Solana asks operators to check archival retention and billing](https://solana.com/docs/rpc/providers), and logs can be truncated ([event guidance](https://solana.com/docs/programs/anchor-events)). Test whether the prototype's 32-root window gives users enough time to prove, retry, and exit during busy periods.
2. **Browser evidence:** Record 100-run warm p95 for every private action and public exit on supported 8 GB Chrome, Firefox, and Safari desktops; capture first-use artifact download, actual process memory, and wallet/RPC transaction acceptance. Headless Brave alone does not satisfy this gate. The documented gate is p95 under 30 seconds for each proof type.
3. **Security and economics:** Independent review of Circom constraints, proof ABI, compiler/prover licensing, payload format, address derivation, history privacy, nullifier rent, fees, and a safe trusted setup. The installed `circom2`, `circomlib`, and `snarkjs` packages each declare GPL-3.0; this test stack is not a cleared production dependency. The local nullifier PDA is rent-funded by each submitter; the fixture's tiny note fee does not cover that cost. The local ASP root setter, fixture origin, and root-window policy are expressly nonproduction. A fresh npm advisory query failed because the registry DNS was unavailable; rerun dependency audits before choosing a stack.
4. **Product/operations/legal:** Set a realistic two-input limit only after complete browser and wallet tests. Resolve fee sponsorship and self-submitted exit UX, token freeze behavior, signer quorum, cap, geography, and written legal assessment. These remain open in the decision register.

**Implementation boundary:** The original pool source and README explicitly forbid deploying their fixed-key artifact. The user separately approved an isolated, test-only Devnet artifact and a recoverable disposable admin for setup; Jupiter signed every customer-like action. The live trial used only Devnet SOL. Its public phase-1 entropy, fixture origin, and simplified authorities prevent any production trust claim. Review and simulate each further Devnet transaction before submission.

`devnet-harness/prepare.mjs` produced six distinct phase-2 test keys in an isolated `/private/tmp/whirlpool-devnet-*` tree and compiled a separate pool artifact offline. The shield verification key and program hash differ from the fixed-key local artifacts. A shield → one-input transfer → revoked, paused current-holder exit proof journey was regenerated against these keys; the matching isolated LiteSVM pool test passed. The later, separately approved Devnet trial used the 119,160-byte artifact described below. Both paths reuse public phase-1 entropy and retain fixture origin and simplified authorities. These are research artifacts only.
