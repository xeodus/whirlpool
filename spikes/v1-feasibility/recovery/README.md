# Recovery research candidate

This isolated spike tests a 24-word BIP39 research phrase carrying 256-bit entropy, versioned HKDF-derived viewing and spending material, HPKE output envelopes, and spent-status/witness restoration. It is **not** a production wallet or frozen phrase format. Public fixture seeds must never hold funds. The phrase uses BIP39 words as a checksum-bearing encoding of entropy; it does not use BIP39's wallet seed derivation.

The old `integrate-candidate.mjs` fixture still maps view keys to spending secrets manually; use `../candidate-circuits/scripts/prove-restored-journey.mjs` for the phrase-derived path. That path proves shield, transfer, and current-holder exit from recovered witnesses; `--emit` creates test-only proof/payload binaries for the pool LiteSVM test. The two-output envelope is 589 bytes, within the candidate circuit's 1024-byte cap. No key material is written to generated artifacts.

`src/history.mjs` reads finalized signatures and full transactions through standard Solana JSON RPC, paginates, replays top-level and inner pool instructions, checks roots and ciphertext commitments, and compares the reconstructed state with the finalized pool account. It fails closed on missing transactions. Top-level instructions and a v0 inner instruction using a loaded program address have passed mocked-RPC tests; neither path has been exercised against a live archive. Cross-provider completeness, history retention, RPC throttling, approval witness publication, and malformed ciphertext addressed to this wallet remain open design work. The 32-root pool history is a serious expiry risk.

Run `npm ci`, `npm test`, and `npm run bundle`. From `../candidate-circuits`, run `node scripts/prove-restored-journey.mjs --emit` and repeat with `--asset1`; from `../pool`, run `NO_DNA=1 cargo test --offline --test flow`. In `../candidate-circuits`, start `node scripts/serve.mjs` and open `/journey?runs=100` for browser-built witnesses; add `&asset=1` for the local-token research path. Its `/wallet-check` page reads Wallet Standard capabilities without connecting or signing. `node scripts/check-devnet-rpc.mjs` reads public devnet version, slot, and rent; optionally pass `WHIRLPOOL_DEVNET_RPC_URL` and `WHIRLPOOL_SECONDARY_RPC_URL` through local environment variables. Never put an RPC credential in source, a browser URL, or a committed file.

Actual archival RPC backfill, fresh-device chain recovery, recipient address UX, key handling, and independent cryptographic review remain separate gates. See [Solana's transaction response](https://solana.com/docs/rpc/json-structures), [v1 read requirements](https://solana.com/docs/core/transactions/versioned-transactions), and [the phrase library](https://github.com/paulmillr/scure-bip39).
